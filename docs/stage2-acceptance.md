# 第二阶段目标模板装配：实现与验收

日期：2026-10-15。

## 处理流程

上传任意名称的现有 XLSX 源文件 → 第一阶段标准化 → 设备档案校验 → 技术参数唯一性和关联校验 → 固定目标模板副本装配 → 最终文件回读和模板保护校验 → 下载 XLSX。

源文件名称仅用于下载文件命名，不参与字段识别、校验、映射或模板选择。全流程由一次上传和一次点击完成，中间工作簿只在浏览器内使用。

## 主要文件

- `dist/engine.js`：保持原日期、资产ABC、设备代码JSON及编码映射规则，新增标准化双表记录和来源元数据输出。
- `dist/assembly-rules.js`：集中定义目标模板路径、字段别名、明确必填字段和关键表头。
- `dist/assembly.js`：第二阶段校验、重复明细、模板装配和最终文件保护检查。
- `dist/app.js`：贯通两阶段，显示六步状态、全部重复组、真实源行号、对应值和非阻断提示；失败时撤销旧下载。
- `dist/index.html`、`dist/style.css`：在原页面上增加处理进度和问题明细，保留原页面风格和映射管理入口。
- `dist/templates/设备档案导入JLTY0714.xls`：原模板字节副本。
- `dist/templates/template-contract.json`：全部Sheet、顺序、隐藏状态、表头XML与公式的固定结构基线。

## 字段映射

所有字段按名称识别，目标列位置从模板表头读取；不存在新增列操作。

| 源字段 | 目标字段 | 依据 |
| --- | --- | --- |
| 设备编码（设备位号） | 设备编码 | 本次明确要求 |
| 设备代码 | 注册代码 | 本次明确要求，写入第一阶段已标准化的JSON文本 |
| 设备型号 | 规格型号 | 双方模板批注中的内部字段标识相同 |
| 位置编码 | 区域位置.区域编码 | 双方内部字段标识相同 |
| 位置编码名称 | 区域位置.区域名称 | 双方内部字段标识相同 |
| 设备详细位置 | 详细位置 | 双方内部字段标识相同 |
| 制造商名称 | 制造厂 | 双方内部字段标识相同 |
| 供应商名称 | 供应商 | 双方内部字段标识相同 |
| 设备使用年限 | 使用年限 | 双方内部字段标识相同 |
| 设备大类名称 | 专业 | 双方内部字段标识相同 |

其余同名字段直接映射。无法映射的源字段忽略并提示；源文件没有的目标字段留空。多个别名出现不同非空值时阻断，避免擅自取值。

源模板“设备代码”的旧批注指向了其他属性，采用本次明确的“注册代码”映射覆盖该元数据冲突。“设备大类代码”没有已确认的独立目标映射，作为非阻断提示忽略。

## 原始行号与校验

第一阶段从工作表XML的`row.r`读取真实行号，保存到每条记录的`source: {sheet,row}`，与`values`分开存放；不使用数组下标或输出文件行号。

第二阶段只读取第一阶段的`standardized.equipment`和`standardized.technicalParameters`，不重新从原始台账提取技术参数。

设备档案按设备编码检查空值和重复。技术参数按设备编码分组，再按参数名称分组；同组两条及以上即阻断，与参数值相同或不同无关。全部重复组及每条来源的工作表、真实行号和值都会保留。缺少关联设备编码、参数名称、来源行号，或关联不到设备时阻断。

第二阶段校验失败时不加载或写入目标模板，不生成最终文件，不自动去重。

## 模板保护

模板扩展名为`.xls`，实际是OOXML压缩工作簿，因此输出`.xlsx`，不转换或重建其他Sheet。

仅替换“设备档案”和“技术参数”两个Sheet的业务数据区，原表头XML逐字保留；原旧业务尾行全部清理。所有其他压缩包部件逐字节保留，包括隐藏Sheet、批注、图片和控件。

写入前及最终ZIP重新打开后，均对比Sheet数量、名称、顺序、隐藏状态、关系路径、完整表头和公式。再检查未写入部件未变化，并逐行回读两个数据表，确认映射值和行数一致。任一不一致均不返回输出文件。

原始模板SHA256：`838e710c43e4d1786be5bdd088fcbdc479239f47294b9768d0e5a9ae52e40a7c`。源文件及原始模板在测试前后均未修改。

## 验收结果

| 场景 | 结果 |
| --- | --- |
| 正常真实安全阀样本 | 39条设备、234条参数、24个Sheet，生成成功 |
| 同设备不同参数 | 通过 |
| 不同设备相同参数 | 通过 |
| 同设备同参数同值 | 阻断，显示源18、37行，模板装配未启动 |
| 同设备同参数不同值 | 阻断，显示源18、37行及1.80 MPa、1.90 MPa |
| 参数引用不存在设备 | 阻断，显示PSV-404及源71行 |
| 三组重复 | 全部返回18/37、42/56、71/92行 |
| 设备编码为空或重复、参数名为空 | 阻断并返回来源位置 |
| 源列倒序、额外源字段 | 仍按字段名称映射，额外字段提示并忽略 |
| Sheet数量、名称、顺序、隐藏状态、表头改变 | 阻断 |
| 表头公式保留和篡改 | 合法副本逐字保留，篡改阻断 |
| 较小数据集覆盖旧模板 | 无旧业务尾行遗留 |
| 页面控制器一次上传贯通 | 通过，任意文件名可下载；失败后旧下载被撤销 |

第二阶段24项验证通过；原第一阶段43项及空白格式单元格回归11项通过，共78项。

实际产物通过openpyxl和Artifact Tool两个独立解析器重开。已核对全部Sheet及隐藏状态、完整表头、表头样式、校验规则、冻结窗格、数值类型以及其他Sheet的全部值。原模板实际表头公式为0条，另用包含公式的临时副本验证了公式保留和篡改阻断。

实际样本测试显式传入“安全阀→J-AQF”自定义映射；未更改内置编码库，页面沿用原浏览器保存的自定义映射。

## 验证边界与待业务确认

- 未执行真实浏览器点击验收或Microsoft Excel/WPS桌面打开验收；当前环境没有可用的Sites浏览器控制能力。文件已完成独立程序重开与数据检查。
- 已生成目标表预览，但环境缺少可用的中文字体渲染，不能据此确认桌面中文显示效果；未为预览改变最终文件的任何字体或样式。
- 当前明确必填项为设备编码、技术参数关联设备编码和参数名称。原模板没有标注其他必填规则，不擅自推断；目标系统是否有额外必填项仍需现场确认。
- 未连接目标业务系统执行上传验收；目标系统对注册代码JSON及其他字段的最终接收结果仍需现场验证。
- 未提供技术参数时，最终技术参数表清空旧业务数据并保留表头，同时给出提示。
